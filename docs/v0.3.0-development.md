# Fun Ground v0.3.0 development plan

## Release process
1. Develop on a dedicated branch and keep main untouched.
2. Preserve the existing game catalogue, embeds, authentication and monetization behavior.
3. Run available static checks and a real build before declaring code verified.
4. Open a reviewable pull request; do not merge or deploy without owner approval.
5. Owner deploys the approved beta to Vercel.
6. Browser-test the beta, record reproducible issues, fix them, and repeat.
7. Promote to final v0.3.0 only after acceptance checks pass; then update Roadmap and Past Updates.

## Competitive safety
- Every competitive feature gate defaults to disabled unless its server environment variable is exactly true.
- Never expose server feature gates through NEXT_PUBLIC variables.
- Ranked requires reliable Fun Ground-verified results.
- Provider catalogue labels are hints, not proof of multiplayer integration or result verification.
- Do not claim arbitrary embedded games are multiplayer.
- Never award XP, tickets, coins, prizes or leaderboard positions from untrusted client-submitted results.
- Payments, deposits, withdrawals, cash redemption and rewarded-ad rewards are excluded from this foundation.
- Preserve existing Monetag behavior and pending AdSense status.

## Fun Ground game capability tags
- Activity Only: session activity can be tracked; no verified score, winner or result.
- Results Verified: the server can reliably verify the result for that specific game.
- Multiplayer Supported: a real, tested multiplayer integration exists with appropriate permission.

A game may carry multiple tags. No game is approved solely because its source catalogue says multiplayer. The reviewed registry starts empty; each tag requires evidence and review.

## Game integration approval checklist

Before a catalogue game receives any competitive capability tag, record and review:
1. Written permission and the technical terms for embedding, multiplayer use and result collection.
2. The real multiplayer transport and authoritative game-state owner; an iframe alone is not a multiplayer integration.
3. A server-verifiable result contract containing the Fun Ground match ID, game ID, participant identities, outcome/score, a replay or proof reference where available, and an idempotency key.
4. Server-side validation that rejects unknown matches, non-participants, duplicate submissions, impossible outcomes and results outside the match window.
5. Two-account testing for match creation, normal completion, ties, disconnect/reconnect and replay/rematch where supported.
6. Evidence links, integration version, review date and a named reviewer in the capability registry.

A provider label such as "online multiplayer" is discovery metadata only. It does not satisfy this checklist.

## Matchmaking scope
- Quick Match and Ranked Match are separate modes.
- No private invite matches and no pre-match chat.
- Ranked requires verified results and verified player eligibility.
- Disconnects need a bounded reconnect window; game-state restoration is game-specific.
- Draw/rematch is allowed only when the game supports safe restart or replay.
- If no suitable opponent is found within the configured wait, offer retry.
- Match creation, result acceptance and rewards must be server-authoritative and idempotent.

## Confirmed progression and economy decisions

- Lifetime XP and player levels are permanent; there is no level-100 cap.
- Competitive XP resets daily. Competitive rankings are per game, with an overall normalized ranking also planned.
- Rank ladder: Bronze, Silver, Gold, Platinum, Diamond, Mithril, Fun. Players begin at Bronze; rank persists across daily resets, with maintenance checks and at most one-rank demotion for failing the maintenance requirement. Bronze cannot demote below Bronze.
- Promotion requires both an XP threshold and a competitive-performance benchmark.
- Top 10 players per rank are intended to receive daily rewards. Exact reward packages and maintenance/promotion thresholds are not finalized; previously discussed 10/50 maintenance XP and 150 promotion XP are drafts, not approved constants.
- Fun Battle rewards are XP plus a Tournament Ticket, subject to server-verified results.
- No cosmetic rewards are planned.

### Token separation
- Fun Tokens are for major tournament entry only. They can be earned through level-ups/platform rewards and purchased. The level-up reward for reaching level 2 is 10 Fun Tokens; the reward increases by 2% per subsequent level.
- Tournament Tickets are for small tournaments. They may be purchased and may later be earned through approved rewarded ads or eligible Fun Battle rewards.
- Ground Coins are exclusively major-tournament prizes and may only become redeemable for gift cards or money after legal and payment-provider approval.
- Small tournaments use Tournament Tickets; major tournaments use Fun Tokens. These currencies are not interchangeable.
- Payment, cash-out, prize redemption and rewarded-ad earning remain disabled until separately reviewed and approved.

## Beta validation
- Guest browsing, search, categories, game pages, embeds, favorites and sign-in remain functional.
- Catalogue IDs and embed records are unchanged.
- Competitive flags are off by default.
- Unsupported games cannot enter Ranked.
- Client requests cannot award XP, tickets, coins or leaderboard positions.
- Unauthenticated users cannot access player-only actions.
- Firestore denies untrusted match, result and reward writes.
- Mobile layouts and signed-out states are tested.
- No payment, cash-out or ad-reward flow is active.

## Current status
The branch currently adds server-only feature gates, authenticated activity-session tracking, and a transactional matchmaking queue foundation. The approved game registry is empty, so no match can be created for a game yet. Result verification, reconnect/rematch handling, missions, XP/levels/ranks, leaderboard aggregation, reward distribution and full competitive UI remain unimplemented.
